# Comparison claims register

This directory is the source of truth for capability claims in OmniSwitch
benchmark and public comparison material. Do not maintain independent tables.

## Files and schema

- `claims.yaml`: hand-authored data, one row per `(gateway, capability)` pair.
- `schema.json`: version-1 JSON Schema for the YAML data. The renderer enforces
  the same field/status/qualifier checks without an extra runtime dependency,
  plus unique IDs/pairs and valid gateway/capability references.
- `COMPARISON.md`: generated by `bench/tools/render-comparison`; never hand-edit.

Each claim requires:

| Field | Meaning |
| --- | --- |
| `capability`, `gateway` | IDs from the lists at the top of the register. |
| `status` | `yes` = confirmed present; `partial` = present with meaningful scope limits; `no` = confirmed absent; `unknown` = not independently verified. |
| `detail` | Precise mechanism, feature scope, maturity, and edition boundaries. |
| `source_url` | Primary vendor docs/changelog/repository URL, or an OmniSwitch code/test path. Required for every non-`unknown` row. |
| `verified_on` | ISO date the row's evidence was checked; displayed per row. |
| `version` | Product/docs version checked. Distinguish it from the benchmark image pin when they differ. |
| `qualifier` | Optional `beta`, `enterprise`, or `license`; omit when not applicable. |

Qualifiers are not replacements for detail: `beta` marks a maturity boundary,
`enterprise` marks an edition boundary, and `license` marks differing terms.
The renderer rejects any other qualifier and displays the value explicitly.
Adding this optional field does not change `schema_version: 1`.

Stable capability IDs include `self-hosted`, `token-rate-limits`,
`image-generation`, `audio-transcriptions`, and `audio-speech`. The legacy
`semantic-cache` ID remains for downstream compatibility, but the display label
is mechanism-qualified: OmniSwitch implements a **lexical similarity cache**
(normalized token-frequency cosine), not an embedding-based cache.

## Evidence and review rules

1. Competitor feature updates require a dated primary source. An old internal
   comparison table is not vendor evidence. Lack of a mention does not confirm
   absence: use `unknown`, not `no`. Unsupported legacy assertions are retired
   to `unknown`, without inventing replacement facts.
2. OmniSwitch claims cite the implementation/test that was read. Release-candidate
   rows for work in flight are integration-gated: verify the merged feature and
   its source path before publishing or tagging that release.
3. Separate product documentation from tested harness versions. A newer release,
   managed edition, or Enterprise feature does not establish support in an older
   OSS image. Check `bench/gateways/<name>/pin.yaml` for benchmark pins.
4. Before publishing benchmark results, share the applicable config/claims with
   vendor maintainers and allow five business days for comment. Record responses
   in the row detail. Do not publish numeric performance claims without a
   completed, reproducible measurement campaign and raw artifacts.
5. Do not imply exclusive A2A/token-exchange support or broad upstream API
   interoperability. Keep provider counts, cache mechanism, authentication,
   edition, and task-lifecycle boundaries explicit. No compliance certification
   or production-readiness certification is asserted by this register.
6. Do not delete a row to improve a comparison. Retain it as `unknown` if it
   cannot be verified. Managed-tier entries are capability maps, not results
   from the same-host benchmark harness.

## Regenerate and check

After editing the register, run and commit both data and generated output:

```bash
python3 bench/tools/render-comparison
python3 bench/tools/render-comparison --check
python3 -m unittest discover -s bench/tools -p 'test_*.py'
```

CI runs `render-comparison --check`. Both PyYAML and the embedded flat-register
fallback parser preserve optional qualifiers. The fallback is not a general
YAML parser; do not introduce anchors, tags, block scalars, or nested claim
objects without extending it and its tests.
